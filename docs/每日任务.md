**1. 继承**

**3. 抽象类**
答：当子类必须重写父类的方法时 ｜ 抽象类能不能有构造方法：不能

> **批注：两个都要改。**
> ① "子类必须重写父类的方法"不是用抽象类的理由——普通类的方法也能被子类重写，只是**不强制**。"强制重写"是**抽象方法**的作用，不是抽象类的定义。
> 抽象类的真正意义是：**这个类本身不该被创建实例**（比如 `Animal` 不该有实例，只有 `Cat`、`Dog` 才有意义）。
> ② **抽象类可以有构造方法。** 这题答错了，而且是高频考点。抽象类不能被 `new`，但它的构造方法**会被子类的构造方法调用**（`super(...)`），用来初始化父类的字段。

**4. 接口**
答：能否创建实例对象

> **批注：这题答错了。** 抽象类和接口**都不能** `new`，所以这不是区别。
> 真正的区别：
>
> |     | 抽象类               | 接口                             |
> | --- | ----------------- | ------------------------------ |
> | 继承  | `extends` 一个（单继承） | `implements` 多个（多实现）           |
> | 成员  | 可有实例字段、构造方法、普通方法  | 字段只能是 `public static final` 常量 |
> | 语义  | "**是什么**"（is-a）   | "**能做什么**"（can-do）             |
>
> JDK 8 加了 `default`、`static` 方法后，两者"能力"上更像了，但**多实现**和**不能有实例状态**这两条仍是分水岭。

**5. 内部类**
答：成员内部类和外部类的private成员都在外部类里，在本类里能互相访问

> **批注：方向对，机制不准。** `Inner` 是独立的类，不在"外部类里"。关键是**Inner 对象内部持有一个指向 Outer 对象的引用**（`Outer.this`），编译器允许它访问外部类的 `private`。

**③ `removeByName` 里那个 for-each，是"侥幸正确"**

`for-each` 底层用的是迭代器。**在迭代过程中修改集合，迭代器会抛 `ConcurrentModificationException`。** 你这里之所以没炸，是因为 `remove` 完立刻 `return`，迭代器再没被碰过。

**这不是写法对，是运气好。** 哪天有人在 `remove` 后面加一行日志，这行日志就会触发异常。规范写法是：先找到下标，循环结束后再删。

## 附录：10-25 补漏三题的参考答案（答完再看）

**① 抽象类能不能有构造方法？**

能。而且必须有意义地写。抽象类不能被 `new`，但它的构造方法会**被子类的构造方法调用**（`super(...)`），用来初始化定义在抽象类里的字段。典型例子：

```java
abstract class Animal {
    protected String name;
    public Animal(String name) { this.name = name; }   // 抽象类的构造方法
}
class Cat extends Animal {
    public Cat(String name) { super(name); }            // 必须调用
}
```

**② 接口和抽象类最重要的区别？**

|      | 抽象类          | 接口                           |
| ---- | ------------ | ---------------------------- |
| 继承   | `extends` 一个 | `implements` 多个              |
| 状态   | 可以有实例字段      | 只能有 `public static final` 常量 |
| 构造方法 | 有            | 没有                           |
| 语义   | "是什么"（is-a）  | "能做什么"（can-do）               |

一句话：**抽象类管"血缘"，接口管"能力"**。Java 单继承，所以能力只能靠接口叠加——这就是为什么 Spring 里到处是接口。

**③ `==` 比 String 时在比什么？**

比**引用**：两个变量是不是指向堆里同一个对象。

`"+" == "+"` 返回 `true`，是因为两处字面量都指向**字符串常量池里同一个对象**，不是因为它内容一样。所以这是**巧合**，不是规则。反例：

```java
String a = new String("+");
String b = new String("+");
System.out.println(a == b);        // false ← 两个不同对象
System.out.println(a.equals(b));   // true  ← 内容相同
```

`equals()` 才是比内容。你写的 `"+".equals(symbol)` 既比了内容，又因为字面量在前而免了空指针。
