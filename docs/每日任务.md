## 为什么先 Maven 再 MySQL

JDBC 需要 MySQL 的驱动 jar（`mysql-connector-j`）。没有 Maven，你得手动下载 jar、手动配 classpath、换台电脑再配一遍。

Maven 把这件事变成 `pom.xml` 里的一行 `<dependency>`。所以顺序是 **Maven → JDBC**，不能反。

**问题二：`Main` 在 Maven 项目里直接崩了**

我用 Maven 编译后试运行：

```
还没有存档，从空列表开始
Exception in thread "main" java.io.FileNotFoundException:
    out\products.txt (系统找不到指定的路径。)
    at com.campus.trade.ProductManager.saveToFile(ProductManager.java:68)
```

原因：你写的是**相对路径** `out/products.txt`。相对路径是相对"**当前工作目录**"，不是项目根目录，也不是源码所在目录。

- IDEA 跑原项目：工作目录 = 项目根，那里有 `out/` → 能跑
- 跑 Maven 项目：工作目录变了，没有 `out/` → `FileWriter` 建不出文件 → 抛异常

**这不是 Maven 的错，是代码依赖了"运行环境恰好有那个目录"。**

修法（两行，放在 `FileWriter` 之前）：

```java
File parent = file.getParentFile();
if (parent != null && !parent.exists()) { parent.mkdirs(); }
```

**问题三：命令行 `mvn` 用不了（不是你的错）**

```
The JAVA_HOME environment variable is not defined correctly
```

我查了：你的 `JAVA_HOME` 值是 **22 个字符**——`[‪E:\Develop_Java\JDK17]`，第一个字符是 **U+202A（从左到右嵌入符）**，一个不可见字符，大概是复制路径时带进来的。正确应该是 21 个字符。

**影响**：IDEA 内置 Maven 不受影响（用它自己的 JDK 配置），所以你今天能编译；但命令行 `mvn` 全废。

**怎么修**（要改系统环境变量，得你自己来）：

1. Win + R → `sysdm.cpl` → 高级 → 环境变量
2. 找到 `JAVA_HOME`，**手动重新输入** `E:\Develop_Java\JDK17`（别复制粘贴，手打最保险）
3. 确定后**重开** IDEA 和终端，跑 `mvn -v` 验证

**你问的"为什么要 src/main/java"，直接答**

这不是随便定的约定，它让 Maven 知道去哪找东西：

| 目录                   | Maven 认为里面是什么           |
| -------------------- | ----------------------- |
| `src/main/java`      | 生产代码 —— 会被打包进最终 jar     |
| `src/test/java`      | 测试代码 —— 只在跑测试时编译，不进 jar |
| `src/main/resources` | 配置文件 —— 打包时复制进 jar      |
| `target/`            | 编译产物 —— 可随时删，Maven 会重建  |

**不按这个放会怎样**：Maven 根本不去看那个目录。**不是报"路径不对"，而是默默什么都不编译**，然后你运行时报 `ClassNotFoundException`——比直接报错难查得多。

这就是"约定优于配置"：按它的规矩放，一行配置都不用写。
