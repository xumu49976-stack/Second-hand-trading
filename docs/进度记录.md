- AI 使用情况：AI 通读全部代码列出 4 处问题（参数未用、字符串用 `==` 比较、校验失败后对象仍被创建且价格变 0、库存可减成负）。其中 3 项当天按提示自行修复；`==` 一项**故意暂不修**，等第 12 章 p126–p127 学完字符串比较后自己判断
- 验收结果：V0.1 四条**全部通过**（当晚补齐）——封装闭环（构造方法调 setter，校验只一处）、按数量增减库存、非法输入拦截、两个非法对象均已展示观察
- 关键发现：非法字段被**静默置为默认值**（价格为负 → `0.0`；库存为负 → `0`），其他字段照常生效，产生"半成品对象"。若入库会出现标价 0 元的商品
- 当日提问与回答：
  - 问"价格为什么是 0"→ 答"负数时只打印提示，没有执行赋值语句，字段停在默认值"（判断正确）
  - 问"校验失败怎么让调用方知道"→ 答"让 setPrice 返回标志值，不同值代表不同原因；或不在构造方法里调 set，单独写判断"
  - 教练批注：返回标志值的方向正确，但多原因用错误码属于过度设计（现阶段 `boolean` 足够）；"不在构造方法里调 setter"是**倒退**，会把刚合并的校验重新拆成两处。真正的难点是构造方法没有返回值可用，需靠异常解决
  - 内部类笔记"Outer.this 记录私有成员地址"表述不准确 → 应为"持有外部类对象的引用"，且访问私有成员靠编译器层面的同类特权（nestmate / 合成访问器），非运行时权限检查
- 练习：`InnerDemo`（外部类 + 成员内部类 + `Outer.this.secret` + `new Outer().new Inner()`）写在 `Java_Learn` 项目里，写法正确，未污染 V0.1
