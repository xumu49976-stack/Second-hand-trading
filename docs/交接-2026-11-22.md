## 4. 已完成的功能

### 实体层 `Product`
- 三个字段 `name` / `price`（double）/ `stock`，全 private + getter/setter
- 构造方法强制校验：名称非空、价格非负、库存非负，失败抛 `InvalidPriceException` / `IllegalArgumentException`
- 重写了 `equals` / `hashCode`（三个字段）和 `toString`

### 数据访问层 `ProductDao`（7 个方法，全部 `try-with-resources` + `PreparedStatement`）
| 方法 | 说明 |
|---|---|
| `findAll()` | 查全部，封装成 `List<Product>` |
| `findById(long)` | 按 id 查单个，找不到返回 null |
| `findByName(String)` | 按名称查，返回同名商品列表 |
| `insert(Product)` | 插入，返回是否成功（`executeUpdate() > 0`） |
| `updateStock(long, int)` | 改库存，返回是否成功 |
| `deleteById(long)` | 删除，返回是否成功 |
| `existsByName(String)` | 存在性检查（`select count(*)`） |

连接信息在静态代码块里从 `jdbc.properties` 加载到三个 static 字段。

### 业务层 `ProductManager`
- `addProduct` / `findAll` / `deleteById` / `exists` / `searchByName` —— 直接委托给 DAO
- `updateStock` —— **业务校验**：`stock < 0` 直接拒绝，不调 DAO（这就是业务层存在的意义）

### 数据库
- 库 `second_hand`，字符集 `utf8mb4` / `utf8mb4_0900_ai_ci`
- 表 `product`：`id` BIGINT UNSIGNED 自增主键、`name` VARCHAR(100)、`price` **DECIMAL(10,2)**、`stock` INT、`category_id` BIGINT UNSIGNED 可空
- 表 `category`：`id`、`name`
- 外键 `fk_product_category`：`product.category_id → category.id`（默认 RESTRICT 行为）
- 当前数据：3 条商品（康师傅红烧牛肉面 4.50/99、米雪 100.00/12、香飘飘 2.50/199），2 个分类（数码、食品）

### 工程化
- Maven 工程迁移完成：`com.campus:second-hand-trading`
- 密码外置到 `jdbc.properties` 并加入 `.gitignore`
- `commons-io` 依赖已引入并在 `Main` 里实际使用（`FileUtils.readFileToString`）

## 5. 最近解决的 bug（按重要性倒序）

### ① `try-with-resources` 被重构弄丢（11-21 → 11-22 修复）
重写 `ProductDao` 时把 7 个方法的资源关闭全删了，连接从不关闭。**实测证据**：
- 同一 JVM 连调 `findAll()` 200 次 → **没炸**（GC 回收 Connection 时 Connector/J 顺手 abort 了）
- 但把连接拴在 List 里不让 GC 回收 → **第 150 次 `Too many connections`**（`max_connections = 151`）

**已恢复**：7 个方法全部改回 `try (Connection ...; PreparedStatement ...; ResultSet ...)`。
**状态：已改但未提交。**

### ② `jdbc.properties` 读不到
静态代码块用 `ProductDao.class.getClassLoader().getResourceAsStream("jdbc.properties")` 加载。
关键是 `src/main/resources` 必须在 classpath 上：
- IDEA 会自动加
- **命令行跑必须手动加**，否则 `getResourceAsStream` 返回 null，后面 `props.load(null)` 抛 NPE

现已能正常加载（`/out` 手工跑时把 `src/main/resources` 加进了 classpath）。

### ③ 删除失败却报"成功"
```java
} else {
    System.out.println("删除成功！！");   // 失败也报成功
}
```
已改为"删除失败"。

### ④ 硬编码主键导致脚本只能跑一次
`insert into product values (4, ...)` → 第二次跑主键冲突。已改为 `insert into product (name, price, stock) values (?, ?, ?)` 交给自增。

### ⑤ SQL 注入
字符串拼接的查询，输入 `' OR '1'='1` 把整张表拖了出来（亲眼验证）。
已改用 `PreparedStatement` + `?` 占位符。
**注意**：防注入的机制**不是转义**，而是"SQL 结构先编译固定，参数只当数据、不参与语法解析"。

### ⑥ 自定义异常继承错了
`InvalidPriceException extends RuntimeException` 导致 `catch (IllegalArgumentException)` 接不住，程序崩。
已改为 `extends IllegalArgumentException`。

## 8. 这个学生的学习特点（新会话必须知道）

1. **会主动质疑**：曾直接质问"有必要加 try-with-resources 吗？我直接 close() 不行吗"。**这是优点**，不要压制；用实验数据回答他，他会接受。
2. **重构时容易弄丢已有正确性**：`try-with-resources` 就丢过一次。每次重构后要重新验证之前修过的问题。
3. **"看视频"不等于掌握**：`CASCADE` vs `RESTRICT` 看过视频仍答反了。所以每个知识点都配了"**故意踩坑**"环节——必须亲手制造一次错误，把报错原文贴回来。
4. **代码习惯在变好**：已经在用 conventional commits（`build:` / `feat:` / `docs:` / `refactor:`），提交信息写得清楚。
5. **明确要求**：他在每日任务文档里写的每条批注/疑问，都要**逐条回应**，不能敷衍。
6. **容易把任务的"注释掉"当成"删掉"**：反复纠正过多次。
